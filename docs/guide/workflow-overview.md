# ワークフロー全体像

## 5 フェーズ + 判定ゲート

```
Phase 1: AI 検索意図の分析とエンティティ・リサーチ
  │  Strategist & Researcher が担当
  │  競合分析、NLP エンティティ抽出、AI 検索意図マッピング
  │
  ▼ [方向性判定] コンテンツの差別化ポイントは明確か？
  │  → No: Phase 1 を再調査
  │
Phase 2: AI 親和性の高いアウトライン設計
  │  Strategist & Researcher が担当
  │  質問ベース見出し、エンティティ割当、モジュール設計、CTR 最適化タイトル
  │
  ▼ [アウトライン承認] 人間レビュー必須 ← 最重要ゲート
  │  → No: Phase 2 で再設計
  │
Phase 3: リサーチ特化 AI と Claude のハイブリッド執筆
  │  Module Creator が担当
  │  Perplexity AI 等でファクト取得 → Claude で構造化執筆
  │
  ▼ [草稿完成判定] 全セクション執筆済みか？
  │  → No: Phase 3 で追記
  │
Phase 4: セマンティック・レビューとエンティティ一貫性監査
  │  Auditor が担当
  │  エンティティ一貫性、パワーフレーズ、内部リンク、トピッククラスター連携
  │
  ▼ [品質判定] GEO/SEO 基準を満たすか？
  │  → No: Phase 3-4 を再実施
  │
Phase 5: テクニカル基盤の構築と公開形式への変換（公開先で分岐）
  │  自社サイト等 → Technical Translator（JSON-LD 生成、画像最適化指示）
  │  Medium      → Medium Publisher（英語化、Medium 記法、GPT 画像プロンプト）
  │
  ▼ [公開判定] 公開準備完了か？（Medium の公開操作は人間が行う）
```

## マルチエージェント体制

```
                  ┌─────────────────────┐
                  │  Orchestrator       │
                  │  （編集長）           │
                  │  進行管理・判定ゲート  │
                  └────────┬────────────┘
                           │
         ┌─────────────────┼─────────────────┐
         ▼                 ▼                 ▼
┌─────────────────┐ ┌──────────────┐ ┌─────────────────┐
│ Strategist &    │ │ Module       │ │ Auditor         │
│ Researcher      │ │ Creator      │ │ （監査役）        │
│ Phase 1-2       │ │ Phase 3      │ │ Phase 4         │
│ ※執筆しない     │ │ ※調査しない   │ │ ※書き直さない    │
└─────────────────┘ └──────────────┘ └─────────────────┘
                           │
              ┌────────────┴────────────┐
              ▼                         ▼
     ┌─────────────────┐      ┌─────────────────┐
     │ Technical       │      │ Medium          │
     │ Translator      │      │ Publisher       │
     │ Phase 5（自社等） │      │ Phase 5（Medium） │
     │ ※編集しない      │      │ ※公開しない      │
     └─────────────────┘      └─────────────────┘
```

各エージェントには明確な**責任境界**がある。例えば Module Creator は提供されたファクトデータのみで執筆し、自らリサーチは行わない。この分離がハルシネーションを防ぐ。

## フィードバックループ

ワークフローは一方通行ではない。品質基準を満たさない場合は前のフェーズに戻る。

| 状況 | 戻り先 | 例 |
|------|--------|-----|
| 差別化ポイントが不明確 | Phase 1 | 競合調査の追加 |
| アウトラインが不承認 | Phase 2 | 見出し構造の見直し |
| ファクト不足で執筆困難 | Phase 1-2 | 追加リサーチ |
| 品質基準未達 | Phase 3-4 | 修正指示の反映 |
| テクニカル要件不備 | Phase 5 | スキーマ修正 |

戻る場合、記事の `README.md` のステータスが「🔁 再検討中」に更新される。

## ステータス管理

各記事の `README.md` にステータステーブルがある。

| 記号 | 意味 |
|------|------|
| ⬜ | 未着手 |
| 🔄 | 進行中 |
| ✅ | 完了 |
| 🔁 | 再検討中 |
| ⏸️ | 保留 |
| ❌ | 中止 |
