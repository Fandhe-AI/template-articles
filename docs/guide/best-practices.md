# ベストプラクティス

## プロンプト設計

### XML タグによる情報分離

プロンプト内の情報は XML タグで役割を明示する。

| タグ | 用途 |
|------|------|
| `<context>` | 背景情報・コンテキスト |
| `<instructions>` | Claude への具体的な指示 |
| `<input>` | 処理対象のデータ |
| `<examples>` | 期待する出力の例示 |
| `<documents>` | 複数ドキュメントのコンテナ |

ネスト構造で引用追跡を可能にする:

```xml
<documents>
  <document index="1">
    <source>出典名</source>
    <document_content>テキスト</document_content>
  </document>
</documents>
```

### Long Context の配置最適化

LLM はテキスト中間部の情報を無視しやすい（Lost in the middle 現象）。

- **上部**: 長文のガイドライン、背景情報、リサーチデータ
- **下部**: 具体的な要求・指示（Queries）

この配置だけで応答品質が最大 30% 向上する。

### マルチショット・プロンプティング

`<examples>` タグで「良い例」と「悪い例」の両方を示す。Module Creator が Write to be quoted フォーマットを正確に再現するために不可欠。

## トークン最適化

### CLAUDE.md の原則: Concise is key

- Claude が既知の一般的な SEO 知識は省略する
- GEO 固有のルールのみ記述する
- 過剰な説明はトークンコストに見合わない
- コンテキストウィンドウは有限の共有リソース

### エージェントの責任分離

単一エージェントに全てを任せると:
- コンテキストウィンドウを圧迫する
- ハルシネーションのリスクが増大する
- 品質の検証が困難になる

役割を分離することで:
- 各エージェントのプロンプトが簡潔になる
- 入力データを最小限に絞れる
- 出力の検証ポイントが明確になる

## 記事作成のコツ

### ハイブリッド執筆の実践

1. **Perplexity AI** でセクションごとにファクトを取得する
2. 引用元 URL を必ず記録する
3. 取得したデータを `<fact_check_data>` タグで Claude に渡す
4. Claude が事実データのみで文章を構成する

Claude 単独で文章を生成させない。これがハルシネーション防止の核心。

### エンティティ辞書の維持

- 新しい固有名詞が登場したら辞書に追加する
- 四半期ごとに辞書を見直す
- パートナー企業の名称変更等に追従する

### 継続的な更新

AI モデルは情報の鮮度を高く評価する。

- 四半期ごとに最新データ・事例を追加する
- `lastModified` の日付を最新に保つ
- 新しい FAQ を追加する
- 古くなった統計データを更新する

## アンチパターン

| やりがちなこと | なぜダメか | 代わりにやること |
|-------------|----------|-------------|
| ワンショットで長文を生成 | ハルシネーション・品質低下 | 5 フェーズに分割 |
| キーワードの詰め込み | AI は意図と文脈を解釈する | 自然な表現で多様に |
| 曖昧な形容詞 | AI は具体性を評価する | 数値・固有名詞で裏付け |
| 物語的な導入 | AI は冒頭を重視する | 結論ファースト |
| エンティティの表記揺れ | AI に曖昧さを与える | 辞書で一貫性を維持 |
| アウトラインを AI 任せ | 方向性がずれる | 人間が必ずレビュー |
