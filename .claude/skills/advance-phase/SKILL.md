記事 `$ARGUMENTS` の現在のフェーズを完了し、次のフェーズに進む。

## 手順

1. 記事ディレクトリの確認
   - `articles/$ARGUMENTS/` が存在すること
   - `articles/$ARGUMENTS/README.md` を読み、現在のフェーズ（🔄 進行中）を特定する

2. 現フェーズの完了条件を検証する

   | フェーズ | 必須ファイル | 完了条件 |
   |---------|------------|---------|
   | 1. リサーチ | `01-research.md` | AI 検索意図 5 件以上、エンティティリスト、差別化ポイント 3 件 |
   | 2. アウトライン | `02-outline.md` | タイトル確定、H2 見出し 3 件以上、エンティティ配置マップ |
   | 3. 執筆 | `03-draft.md` | 全 H2 セクション執筆済み、ファクトデータ記録済み |
   | 4. レビュー | `04-review.md` | 修正指示リスト作成済み、全修正反映済み |
   | 5. テクニカル | `05-technical.md` | JSON-LD 生成済み、公開チェックリスト全項目完了 |

3. 判定ゲートを実施する
   - ユーザーに判定材料を提示する
   - Go / No-Go / 条件付き Go を確認する
   - No-Go の場合: 差し戻し先フェーズと理由を提示する

   | ゲート | 確認事項 |
   |--------|---------|
   | 方向性判定（1→2） | 差別化ポイントは明確か？ |
   | アウトライン承認（2→3） | **人間が内容を確認・承認したか？**（最重要） |
   | 草稿完成判定（3→4） | 全セクションが執筆済みか？ |
   | 品質判定（4→5） | 全修正指示が反映されたか？ |
   | 公開判定（5→完了） | 公開準備が完了したか？ |

4. Go の場合、README.md を更新する
   - 現フェーズ: 🔄 → ✅ に変更、更新日を記入
   - 次フェーズ: ⬜ → 🔄 に変更、更新日を記入
   - ドキュメントリンクを追加

5. 次フェーズの担当エージェントにコンテキストを引き継ぐ
   - Orchestrator エージェントの委任マップに従い、必要なコンテキストを選別する
   - 次フェーズのプロンプトテンプレート（`.claude/rules/phases/`）を参照して開始する

6. Phase 5 が完了した場合
   - 全フェーズのサマリーを生成する
   - ステータスを全て ✅ に更新する
